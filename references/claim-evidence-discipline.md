# 主张—证据纪律（Claim–Evidence Discipline）

> **版本元数据**：`version: v1.0` ｜ 生效 2026-10-14 ｜ 状态：现行有效 ｜ 合入 PR：`references/prs/PR-008-claim-evidence-and-proposal-structure.md`
> **中央真相源之一**（PR-008 新增）。本文件定义专家团在外发材料中**逐条主张与证据的配对规则、动词强度分级、程度表述的量化要求、以及不得过度整改的保留清单**。
> 与 `evidence-spec.md`（来源与证据分级）、`style-guide.md`（文风与词表）、`redlines.md`（诚实边界）分工配套；全团引用，不得各写各的。
> **来源说明**：本规范吸收自外部 Skill 资产 `academic-humanizer`（AIScientists-Dev，SKILL.md v0.3.3，MIT）的 Layer 2 / Layer 3 / Layer 4 判据，经**部分整合**（抽取内核、改写为中文商务售前语境、剔除学术专属条款），经用户确认执行（PR-008）。
> **不适用**：非外发用途的内部草稿、工作笔记、notes 目录下的中间推理稿。

## 一、适用范围与豁免（先读本节，避免误报）

### 1.1 适用对象

面向客户、评审、领导或公众的外发材料，含：方案、投标文件、申报材料、调研报告、汇报材料、宣传材料。

### 1.2 四类豁免（命中不判违规，但须记录依据）

| # | 豁免情形 | 说明 |
|---|----------|------|
| 1 | **引述原文** | 直接引用政策原文、标准条款、客户书面材料、第三方报告原话的，按原文保留，含其中的程度词与修饰语 |
| 2 | **固定表述** | 招标文件、申报指南、合同条款中业主/主管部门已固定的表述（如"具备同类项目经验""满足相关要求"），不得为满足本规范而改动 |
| 3 | **行业术语** | 有行业文献或标准依据的固定用法（与 `style-guide.md` §1.2 同一判定机制） |
| 4 | **法规定性用语** | "强制""应当""不得"等法规用语按原义保留（与 `style-guide.md` §4.3 一致） |

**判定纪律**：豁免须**逐条记录依据**（引用出处 / 条款编号 / 行业文献），不得以"这是固定表述"概括豁免。记录结论进 ver 核验输出。

## 二、主张—证据配对（核心规则）

### 2.1 基本要求

**每一条经验性主张，必须能回答"凭什么"。** 每条此类主张须至少绑定以下一项，缺项即判「待确认」：

1. 数字（含量纲与口径）；
2. 表 / 图编号（并说明该表图在文中的位置）；
3. 条款编号（政策号、标准号、合同条款、招标文件条目）；
4. 明确的来源标注（按 `evidence-spec.md` §三 台账口径）。

### 2.2 处理方式（二选一，不得含糊放行）

| 情形 | 处理 |
|------|------|
| 证据存在但未写入 | **补充证据指针**（把数字、表号、条款号写进该句） |
| 证据确实不存在 | **弱化主张**至当前材料可支撑的强度，或删除该主张；不得用模糊表达掩盖缺口 |

### 2.3 禁止做法

- 不得新增、删除或修改任何数字、结果、公式、引用与条款编号——改写只处理表述层，不触碰事实层；
- 不得用改写手段**掩盖证据缺口**（把"缺乏验证"写成"表现良好"属严重违规）；
- 不得将**限定条件下的结论**外推为普遍结论。

## 三、动词强度分级（不得强于证据）

### 3.1 三级动词强度对照

| 强度 | 适用证据状态 | 中文表述（推荐用词） | 禁止越级使用 |
|------|--------------|---------------------|--------------|
| **强** | 已通过验证 / 已有实测数据 / 已有条款明文规定 | 已实现、已完成、达到、符合、满足 | — |
| **中** | 有明确依据但尚未在本场景验证 / 依据来自同类场景 | 具备……能力、支持、可达到、预计达到、经测算为 | 不得写成"已实现 / 已部署 / 已使用" |
| **弱** | 原理可迁移 / 依据为推断 / 尚未验证 | 有望、可支撑、建议通过……确认、初步判断为 | 不得写成"具备……能力" |

### 3.2 高后果表述的特别约束

1. 涉及**交付承诺、性能指标、工期、金额**的主张，动词强度须与合同/招标文件可支撑的范围一致；超出部分一律标「需确认」；
2. 涉及**新行业、新场景、新客户**的适配能力，按 `redlines.md` 红线 1 / 6 处理（不得称已部署，须标假设并建议验证）；
3. 中文材料中"国内领先 / 行业领先 / 国际先进"类定性表述，须绑定可核验依据（检测报告、标准符合性、第三方评价），否则删除。

## 四、程度表述须量化（规模词与模糊语）

### 4.1 须绑定数量的规模词

以下词若出现，须在该句或紧邻句给出**具体数量、范围或条件**；不能给出时删除或改为定性陈述：

**规模类**：全面的、大量的、多项、广泛的、深入的、充分的、丰富的、完善的、一系列、众多；
**效果类**：显著提升、大幅降低、明显改善、大幅优化、有效解决。

**改写示例**：
- 「广泛适用于各类场景」→「适用于 A、B 两类场景（见 3.2 节）」；
- 「显著降低运维成本」→「按当前参数测算，运维工时下降约 30%（假设条件见附录）」；
- 「多项成功案例」→「N 个同类项目案例（清单见附件 X）」。

### 4.2 须量化或删除的模糊 hedge

较为、相对、一定程度上、某种程度上、基本上、总体而言（作程度用时）、有所、略显。

**处理**：给出数或范围；无法量化时，改为明确的条件句（"在 A 条件下"）或直接删除。

### 4.3 程度词与红线的关系

本节要求**不得削弱** `redlines.md` 的诚实边界：降本数字的「示意·假设」标注、精度适用边界、新场景 POC 建议等表述，属**必须保留**的限定，不属需弱化的模糊语。

## 五、可读性阈值（长句与堆叠）

| # | 判据 | 处理 |
|---|------|------|
| 1 | 单句**超过约 60 字**，或含 **3 个以上分句**（逗号/分号连接的独立语义单元） | 拆分；一句表达一个主要判断 |
| 2 | 同类连接词（此外 / 同时 / 并且 / 因此）**连续多句开头** | 改为由逻辑关系自然衔接，或合并句 |
| 3 | 同一段落内**同一程度词重复 ≥3 次** | 择要保留一处，其余改为具体表述 |

**说明**：本节为可读性判据，不构成对交付件句式的硬性上限；技术描述、条款转述等确需长句的场景，由 ver 按上下文判读。

## 六、不得过度整改的保留清单

改写过程中，以下内容**必须保留**，不得为追求"简洁干净"而删除或简化：

1. **证据限定的限定语**：可能、在……条件下、需验证、初步结果显示、以实测为准；
2. **适用范围与前置依赖**：适用区间、边界条件、依赖的客户侧输入；
3. **诚实边界**：`redlines.md` 的六红线与第三方报告 caveat，按原义保留；
4. **技术内容**：正式定义、命名型号、指标名称、技术术语、公式、符号、单位；
5. **事实层全部要素**：数字、结果、引用、条款编号（与 §2.3 一致）。

**反向约束**：限定语与适用范围不得被"优化"掉——**把有条件的表述改成无条件表述，属本规范项下的严重违规**（与 ver「虚假承诺一票否决」同一后果等级）。

## 七、核验执行（ver M5 检查项）

ver 核验时，对外发材料执行三步：

1. **主张清点**：逐条提取经验性主张（性能、效果、能力、案例、进展类陈述）；
2. **配对核对**：每条主张是否有数字/表图/条款/来源四者之一（§二）？动词强度是否与证据状态相符（§三）？
3. **表述核对**：规模词与模糊语是否有量化或条件绑定（§四）？限定语与适用范围是否完整保留（§六）？

**判定归并**：任一条主张无证据绑定 → 该条判「待确认」；出现越级承诺或限定语被删除 → 判「修订后复核」；涉及红线越界 → 按 `redlines.md` 规则判「禁止外发」。

**辅助扫描**：`scripts/check_style_words.py` 的 `--weak` 档提供规模词/模糊语的**提示级**计数（筛子定位，判读在 ver），不计入三类禁用词的清零口径。

## 八、与既有文件的关系

| 文件 | 关系 |
|------|------|
| `evidence-spec.md` | 管「来源与证据的**分级与登记**」（来源是一手还是二手、证据属事实还是推断）；本文件管「**主张与证据的配对**」（每条主张是否绑定了证据、动词是否越级）——前者是证据库建设，后者是使用纪律 |
