# 中央红线与诚实边界（全团唯一真相源）

> 本文件是**售前专家团**的**权威真相源**。团长在组装上下文交接物（Handoff Artifact）的「约束与红线」一节时，须以本文件为唯一出处；`docx-agent` / `mat-agent` 落地与外发时须逐条保留，不得弱化、改写或删除。
>
> **来源说明（重要）**：下列"六红线"与"第三方科研/测试报告 caveat"是一套**通用诚实边界范式**，其约束精神源自某真实交付项目的边界经验（如"未在某行业验证的能力不得称已部署""样例测试结论外推须标假设/POC"）。在面向**任意客户、任意行业**的通用场景中，团长与成员应**按场景抽象为泛型诚实红线**，并将本文件作为"如何定义诚实边界"的范式参考，而非逐字套用某一交付的原文。新增/调整红线须由团长在交接物中显式声明并标注依据。

## 一、六红线（诚实边界底线）

| # | 红线 | 含义 | 客户版（对外）内化表达示例 |
|---|------|------|---------------------------|
| 1 | 不称已部署 / 已使用 | 仅在某一行业/客户验证或仅为原理可迁移的能力，不得表述为"已在 X 行业使用/已部署" | 写为"该技术在 Y 领域已有批量验证，其向新场景的迁移建议通过一次轻量验证确认"，不写"已在 X 使用" |
| 2 | 第三方科研/测试报告须附 caveat | 引用第三方科研/测试报告必须同时附完整 caveat，不得单独引用结论 | 报告结论与 caveat 同源同文出现，置于相关章节或脚注 |
| 3 | 降本数字标示意·假设 | 任何降本/增效数字均为示意，须标注「假设」与置信度 | 写为"按当前参数测算示意区间，实际以落地验证为准" |
| 4 | 标称降级以实测为准 | 材料/部件标称值须以实际来样实测值为准，标称仅作参考 | 实测值优先于标称，差异点显式说明 |
| 5 | 精度适用边界 | 精度指标仅适用于一致性/趋势/预警场景；超出标定适用范围（如极端工况/高压段）须标假设 | 明确适用区间，不在边界外外推精度 |
| 6 | 新场景适配挂假设·须 POC | 向新行业/场景适配须标「假设」并建议 POC 验证，不得写成已确认能力 | 写为"新场景适配为假设，建议通过 POC 确认" |

## 二、第三方科研/测试报告 caveat（完整版，须逐条保留）

引用第三方科研/测试报告时，须至少保留以下边界（示例原文口径）：

- 报告性质为**科研性质**，非认证/检测合格结论；
- **仅对来样**负责，不代表同型号批量产品；
- 结论仅供客户**内部评估参考**；
- **无社会证明**效力，不得作为对外资质背书；
- **不得用于司法维权**依据；
- **不得用于强制认证**；
- 报告具**时效**，须标注出具日期与有效期限，过期结论须重新验证；
- 来样仅代表所送样本，**非其他场景/领域样**，结论外推至其他场景须以实际验证为准。

> 客户版内化表达（不单列免责章）：写为"该测试报告可供贵司内部评估参考，其结论外推至新场景须以实际验证为准"，自然带出，不堆砌免责清单。

## 三、使用规则（全团统一）

1. 团长组装交接物时，在「约束与红线」一节**内联本文件的现行红线文本**（按场景抽象后的泛型版本），作为下游唯一约束。
2. `mat-agent` 生成对外材料时，将红线实质**内化于叙述**，不单列"诚实前提/免责章"，但红线实质不得削弱。
3. `docx-agent` 落盘 .docx / PDF 时，六红线与 caveat 须**逐条可见、同源同文**，置于对应章节或脚注。
4. `ver-agent` 核验时，将"红线是否完整保留、有无越界表述"作为强制维度；出现越界（如"已在 X 使用/已降本"）一律判「禁止外发」。
5. 任何成员发现红线与场景冲突，须在「待确认问题」中向团长提出，由团长修订后回流，不得自行删改。
6. **`references/` 自身更新的 PR 纪律**：本文件与 `knowledge-index.md` 等属于全团真相源，其描述会随交接物注入成员上下文（性质等同 MCP 工具描述，污染会级联下游）。任何回写改动**不得由成员在会话中直接改主分支**，须走 `references/governance.md` 的 **PR + 异源互审**协议（Proposer 提最小 diff→异源 Reviewer 独立审核→合入重建派生索引）；锁版本、拒静默更新、可回滚。新增/调整红线须由团长在交接物中显式声明并标注依据，且经 governance 的 PR 流程合入。
