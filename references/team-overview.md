# 项目定位

售前专家团是一套开源的多角色智能体协作团队，由一名总编排和十一位领域专家组成，用于生产可追溯、可外发的报告、方案与各类材料；它针对的是长材料生产中反复出现的三类问题——口径漂移、无据结论与返工失控。

## 团队是什么

售前专家团把一份高质量材料的生产过程拆解为五个阶段：输入消化、调研分析、方案组装、叙事成稿、核验出件。每个阶段由专门角色负责，阶段之间以标准化交接物衔接，上一阶段验收不通过，下一阶段不开工。

团队的全部构成是四类文件：每名成员一份角色定义文件（职责、工作规范、产出结构），一套协作规范（沟通、验收、格式、证据、治理的中央规范文件），一组出件脚本（把版式与纪律固化为可执行代码），以及正式文档的标准样式模板。开源的含义即在此：四类文件以标准文件包形式完整提供，任何人都可以获取、阅读、复用与改造，重建自己领域的协作团队。

## 解决的三类问题

单人或松散协作模式在长材料生产中有三类高频问题，团队的设计逐条对应。

- 口径漂移：同一事实在不同章节、不同载体中表述不一，审校阶段才集中爆发。
- 无据结论：结论缺少来源，无法核验，材料经不起追问。
- 返工失控：交付方向未经确认即动笔，全流程围绕错误假设运转，后期整篇推翻。

对应的设计分别是：结构化交接物与跨源一致性检查应对口径漂移；每条结论强制标注来源应对无据结论；开工前深度追问与全流程闸门应对返工失控。这三项设计在第四章展开。

## 适用读者

- 希望快速了解本团队运作方式的读者：第二章至第四章给出完整机制。
- 打算复用或重建同类协作团队的实践者：第七章给出文件包结构与改造指引。
- 研究多智能体协作机制的研究者：第六章给出经验沉淀与知识治理的工程做法。

# 团队构成

团队共十二个角色，一名总编排负责编排调度与验收汇总，十一位领域专家各负责一个专业面；所有成员只与总编排通信，成员之间不直接对话；成员按需启用，同一阶段并行不超过三人。

## 角色分工

十二个角色的职责划分如下表。总编排不代写任何成员的专业结论，只做编排、验收与汇编；成员之间不直接连接，全部信息经由总编排转发，避免二手信息在成员间扩散。

**团队成员与职责**

| 角色 | 职责 |
| --- | --- |
| 总编排 | 任务拆解、阶段调度、验收退回、汇总成稿 |
| 行业情报 | 行业趋势判断与竞争、风险信号 |
| 政策研究 | 政策适用性转化与必要性论证 |
| 客户洞察 | 客户环境画像与干系人视角 |
| 产品服务 | 分层产品能力匹配与服务边界 |
| 案例管理 | 案例匹配、脱敏与证明材料策略 |
| 数据支持 | 预算测算、数据表与一致性检查 |
| 方案架构 | 分层架构、分期路径与前置依赖 |
| 材料策略 | 叙事策略、结构与受众适配 |
| 输入消化 | 多格式材料结构化抽取与来源标注 |
| 文档输出 | 内容落地为正式文档并执行自检 |
| 核验风控 | 事实核验、一致性核验与外发判定 |

## 各角色运行规则与协同

以下按工作流顺序逐一给出十二个角色的运行规则与协同关系：先一句定位，再列该角色必须遵守的核心规则，随后紧跟其与其他角色的协同方式。规则均摘自各角色的定义文件，是成员回传验收的依据；完整的阶段衔接与五阶段流水线见第三章。

### 总编排（团长）

全团唯一的管理者：理解任务诉求、拆解工作项、按流程调度成员、验收每份回传并汇总成稿。团长只做编排与汇编，不代写任何成员的专业结论。

本角色的运行规则：

- 开工前必须亲自向任务发起人完成需求确认（逐支深度追问），未确认禁止建立团队、禁止开始写作（见第三章）。
- 每份成员回传按四个维度验收：完整性、可追溯性、假设标注、上游一致性；不达标附具体缺口退回修订，同一成员最多两轮。
- 退回修订时须附结构化失败归因，指明第一个出错的步骤与根因类别，供核验风控复核。
- 成员之间不直接对话，全部信息经团长远转；转发只给结论标签、影响面与待办，不转成员原话。
- 对用户只在阶段收口时汇报，过程零噪音；触及红线、预算超限或外发判否时立即上报。

与其他角色的协同关系：

- 上游是任务发起人（需求确认与重大口径拍板），下游是全体十一位成员（派发任务卡与交接物）。
- 维护完整的可追溯链，向下游只下发最小必要子集；同一阶段并行调度不超过三人。

### 输入文档规范

全链路第一站：把任务发起人提供的演示文稿、PDF、Word、表格、图片、网页等多源材料，消化为全团可复用的结构化输入。它管输入怎么规范进来，与文档输出岗的一进一出相对应。

本角色的运行规则：

- PDF 文件强制走专用解析工具，扫描件自动识别并转文字识别，超过二十页的大文件按块读取、跨块合并并标注页码范围。
- 按客户诉求、背景画像、约束红线、预算数字、时间窗、干系人、待澄清七个维度结构化抽取。
- 每条结论标注文件名与页码，保证可追溯；缺页、乱码、前后矛盾一律标注待澄清并给出置信度。
- 对触碰诚实红线的输入（如声称已部署已降本、要求承诺未验证数字）提前向团长预警。
- 确定性工作（格式识别、页码标签、红线信号预检）交给脚本完成，语义归类由成员完成。

与其他角色的协同关系：

- 背景画像与干系人两个维度直接供客户洞察岗使用，后者不重新读原始材料。
- 预算数字供数据支持岗，约束红线供核验风控岗做外发判定基准。

### 行业情报

调研阶段三岗之一：提供行业趋势判断与竞争风险信号，把行业信息转化为可支撑立项的依据。

本角色的运行规则：

- 输出利好、风险、立项依据三类判断，每条标注不确定性来源。
- 提效类断言必须有对照来源，禁止裸写百分比；竞品对标须点名具体替代方案而非泛称市面有同类方案。
- 易过期的结论（模型排名、开源闭源差距等）标注信息时点与失效预期。
- 同区域同类客户对标须说明可比条件，任一不满足时显式标注差异及影响。
- 不编造未发生的合作与案例。

与其他角色的协同关系：

- 与政策研究、客户洞察三岗并行开工，产出汇入立项判断。
- 替代方案预研结果传给案例管理岗与材料策略岗做差异化话术。

### 政策研究

调研阶段三岗之一：把政策语言转化为面向客户的建设必要性说明，回答为什么要建。

本角色的运行规则：

- 严格区分方向性依据与强制要求，未经核验的原文不得写成强制建设要求。
- 每条引用附发文机关、文号、发文日期与可查验来源四要素，仅凭记忆复述的条目一律降为待核实。
- 做时效与冲突检测，过期或被新文替代的政策显式标出，不与现行版本一起进入交付。
- 同一政策条目连续两次核不实即标待核实转人工，不无限查。
- 不夸大政策约束，不预设客户属于任何特定行业。

与其他角色的协同关系：

- 与行业情报、客户洞察三岗并行开工。
- 识别出的强制性红线须指出对应的不可绕过校验点（模板必填项或核验闸门条目），传核验风控岗执行。

### 客户洞察

调研阶段三岗之一：刻画客户小环境与关键干系人视角，回答客户到底要什么、谁说了算。

本角色的运行规则：

- 严格区分已确认事实与推断，推断显式标注；不臆测客户内部人事与预算权限。
- 每条诉求标注代言身份（决策层本人还是业务部门代提）与获取情境，区分本人诉求与转述。
- 客户口径变更时新增带时间的记录条目，新旧并存留痕，不覆盖旧值。
- 每条待澄清问题必须带超时降级方案：超时后采用保守默认口径，并按影响面分级。
- 含客户身份与内部信息的条目标注敏感，不外化到客户版材料。

与其他角色的协同关系：

- 事实底座来自输入文档规范岗的七维度抽取，只补充推断与待澄清，不重抽原始事实。
- 产出的行业上下文块（行业、术语、合规红线、典型场景）供团长组装项目信封下发全团。
- 预算与红线的交叉比对（申报预算对方案报价）与核验风控岗联动主动预警。

### 产品服务

方案阶段第一棒：给出分层产品能力匹配与推荐理由，明确哪些可承诺、哪些需确认。

本角色的运行规则：

- 按核心作业能力、感知与场景扩展、交付与配套服务三层组织产品方案。
- 明确划分可正式承诺项与需确认项，未确认的价格、型号、数量不得写成正式承诺。
- 必须附不承诺项清单（做不到什么、不覆盖什么，不少于三条）。
- 禁用最全、最强、唯一等绝对表述；限定条件与适用范围不得为追求简洁而删除。
- 承诺动词按证据状态分级：已实现、具备可达、有望，不得越级。

与其他角色的协同关系：

- 是方案架构、案例管理、数据支持三岗的上游，其产品分层经团长验收后三岗才并行开工。
- 划定的可承诺边界与核验风控岗共用同一红线：产品岗守前门、核验岗守后门。

### 方案架构

方案阶段三岗之一：设计分层、分期、可解释的能力体系与分阶段价值。

本角色的运行规则：

- 按目标治理、作业能力、作业平台、数据资源、运营服务五层组织架构。
- 每个分期里程碑写明前置条件、完成条件与风险约束三要素，完成条件须可被客观证据判定。
- 架构须可追溯至已确认成果，引用上游结论标签；未确认前置不得标记为可确认。
- 向下游交付时只给产物路径与已确认事实约束，不粘贴全量推演轨迹。

与其他角色的协同关系：

- 依赖产品服务岗的产品分层，在其验收后并行开工。
- 架构范围是数据支持岗测算预算的输入。
- 分期路径与各阶段价值说明传材料策略岗组织叙事。

### 案例管理

方案阶段三岗之一：匹配可证明案例，管理脱敏与公开授权边界。

本角色的运行规则：

- 案例分三层管理：强案例（涉密或客户明令禁发）仅内部论证使用，公开案例须脱敏到无法反推客户，受保护案例须授权加脱敏双控。
- 真实案例写入机构名前必须取得披露授权，未授权一律标假设待检索并去标识化。
- 案例只作可证明方向与同类实践的支撑，不表述为客户已采用。
- 每条已采用、已上线类表述须能指出书面凭证（合同、验收单或客户书面确认），指不出即降级为接触中或试点中。
- 被否与中止的方案与成功案例同权入库，保留完整图景。

与其他角色的协同关系：

- 依赖产品服务岗的产品分层，案例须与产品匹配。
- 差异化话术与行业情报岗的替代方案预研联动。
- 案例清单随核验风控闸门固化，未授权项不得进入可外发判定。

### 数据支持

方案阶段三岗之一：预算测算、数据表构建与数字一致性检查。

本角色的运行规则：

- 无来源数字不得编造，缺输入时明确标注不可测算。
- 比例与金额必须标注依据与单位；保留原值口径（原币种、计费周期、税费口径），不自行换算，口径不一致时不做横向比较。
- 对外成效承诺必须带前后双值与测量口径，禁用显著提升式空泛表述。
- 落盘的测算文件是全团预算数字的唯一事实底座，修订须走版本基线核对。

与其他角色的协同关系：

- 依赖产品服务岗的报价与方案架构岗的建设范围。
- 跨文件数字一致性由脚本自动核查，是核验风控岗核验的前置必跑项。

### 材料策略

成稿阶段：面向受众组织叙事策略、内容架构与页面级素材，只做表达不新增事实。

本角色的运行规则：

- 先建立建设判断再进入方案，产品作为能力支撑自然融入而非罗列能力清单。
- 同一事实底座产出立项汇报版、投标版、领导汇报版多版本，口吻详略随受众切换，不为不同版本编造不同事实。
- 正式客户版把诚实边界内化于叙述，不单列免责章节；正文禁八类工作痕迹，只写结论不写过程。
- 每条经验性主张就近绑定数字、表图编号、条款或来源之一；规模词与效果词绑定数量或条件。

与其他角色的协同关系：

- 依赖此前全部已确认结论（调研与方案阶段的产出），素材须能溯源到上游结论标签。
- 文风自检结果传核验风控岗做终扫，受众与目标版本由团长下发。

### 核验风控

外发前的独立闸门：对事实来源、政策表述、产品承诺、案例授权、数字一致性做核验并给出外发判定。

本角色的运行规则：

- 只消费上游结论、只核验不补写；核验只看原始证据与最终结论，不顺着前序叙述链顺读，防止上游错误因被反复引用而看似可信。
- 给出三级判定：可进入使用、修订后复核、禁止外发。
- 判违规前先做评测系统自检：确认红线与验收标准本身适用于当前场景，标准问题列为待澄清而非直接判成员违规。
- 外发关键件（投标提交、报价定稿、客户发信）启用双核验：由两个不同模型家族独立复核，判否一致才外发，不一致转人工。
- 文本类核验须对全部文件去标签后整体计数，不只查正文，防止拆词漏判；同目录的备份与旧版一并扫描。

与其他角色的协同关系：

- 是文档输出岗开工的前置条件，只有判定通过的定稿才进入出件。
- 按需消费上游的事实、政策、数字类结论（最小必要原则，不接收口播素材类内容）。
- 消费团长回路的失败归因，聚焦根因复核。

### 文档输出

最后一站：把核验通过的定稿落地为正式 Word 文档，默认交付格式，只保真不篡改。

本角色的运行规则：

- 渲染走确定性脚本，成员只做语义组织与核对，不手写排版细节，从源头避免乱码、丢红线、编号错位。
- 标题严禁手写编号，编号权交给模板的自动编号体系，杜绝双重编号。
- 诚实红线逐条落位到附录，不弱化不丢失。
- 渲染完成后必须读回真实文件逐项核验（红线落位、编号连续、表格完整、无乱码），判断权在成员而非脚本退出码。
- 套样式不等于样式生效：表格样式可能被文字级直接字体字号覆盖，图片仅设居中对齐不算套样式，表题与图题也会被写死的字体字号盖掉样式。须以可数判据为准——套用表格样式的段落、题注段落中直接字体字号数均为零，含图片对象的段落未套图片样式数为零；只统计"套了样式"不算通过。编辑器批量插图后须跑修复脚本归位并读回确认；题注不从版面猜测补套，缺失即从文档树重渲。
- 出件不因文件被占用而中断：写入前探测目标能否独占写，被打开则自动输出带时间戳的新文件，旧文件保持不动、不重试也不等用户关闭；版本数量由归档脚本按基名归组收敛（每组保留最近两份，其余移入归档目录，只移动不删除）。
- 四条渲染通道按硬性规则路由：正式交付一律走模板体系，禁用富视觉创作通道。

与其他角色的协同关系：

- 只接收核验风控岗判定通过的定稿。
- 字体、字号、页面版式遵循统一模板规范，不自创格式。

## 依赖与并行规则

任务并非每次都需要全部成员。团队把调度关系分为两类：可并行组与必须串行的依赖链。

- 可并行：调研阶段的行业情报、政策研究、客户洞察三岗可同时开工；方案阶段的架构、案例、数据三岗在产品岗产出验收后并行。
- 必须串行：产品能力结论先行，架构、案例、数据依赖该结论；叙事策略依赖此前全部已确认结论；核验依赖成稿；文档输出依赖核验通过。

成员启用有明确门槛：有客户材料需要消化才启用输入消化岗，涉及对外数字或金额才启用数据支持岗，面向受众组织表达才启用材料策略岗，外发之前核验岗必须启用且不可省略。启用的判定标准是：本次任务如果没有这个角色，结论会不会不同；结论不会不同，则不启用。

同一阶段并行成员上限为三人。超过三人时，总编排的验收成为瓶颈，成员之间经由总编排转发的信息也开始相互干扰，实测中多处结论反复均源于此。

## 模型分派

团队并不要求全员使用同一个模型：各岗位工作特性差异极大，有的判断密集（趋势判断、外发核验，指材料对外发送前的核验），有的确定性高（结构化抽取、脚本渲染核对）。团队按岗位特性把成员分派到不同档位的模型上（档位按模型能力与消耗水平划分），在不引入质量风险的前提下控制单次任务的模型消耗。分派原则是质量优先：只有确定性高、无判断风险的岗位使用快省档，成稿与外发等质量关口与数字岗使用旗舰档（数字岗原用的数学严谨档模型暂停使用，恢复后回原档）。

下表是当前的分派结果。倍率（计费倍数）为平台某日的快照值，实际以客户端当前显示为准；「订阅优先」「夜间折扣」「限时免费」等标签的实际扣费规则以账单为准。

**模型分派表（倍率为快照值）**

| 档位 | 模型（倍率） | 适用角色 | 选择理由 |
| --- | --- | --- | --- |
| 旗舰档 | GLM-5.3（0.69x） | 总编排、材料策略、核验主核、数据支持 | 工具调度最稳、中文行文严谨且数学能力居前，质量关口与数字岗所在档 |
| 顶级复核档 | Kimi-K3.1-Pro（0.97x） | 不日常占用，仅在两核判否不一致时复核 | 最强推理兜底，比同家族更贵的旗舰便宜约四成 |
| 数学严谨档（暂停） | DeepSeek-V4-Pro（0.51x） | 暂停使用（用户指令）；恢复后数据支持与核验副核回此档 | 数学推导扎实、逻辑失误少——暂停期间由旗舰档与强推理档分任 |
| 强推理档 | Xiaomi MiMo-V2.6-Pro（0.13x） | 调研三岗与方案四岗；核验副核 | 综合推理强且成本约为旗舰的五分之一；与主核不同厂商，兼任跨家族副核 |

| 免费备选档 | Hy4 flash（限免）、Hy4 | 用户明确要求再省时启用 | 零成本，但限免随时失效，启用前须确认仍可用 |

分派不是静态的，配套四条升降规则：

- 自动升档：成员产出被验收退回两轮后，第三轮重派时自动升一档（输入类岗位依次升至 GLM-5.3-FlashX、GLM-5.3；调研与方案岗位依次升至 Step-5-Preview、GLM-5.3（数字严谨档模型暂停期间，第三站统一为旗舰档）），升档原因写入任务卡。
- 永不降档岗：总编排、核验、数据、材料策略四岗任何情况不降档——外发判断、数字、成稿质量一旦出错，没有兜底补救的机会。
- 双模型家族核验：外发关键件由旗舰档与强推理档两个不同厂商的模型独立复核，两者都判定通过才放行；一个通过一个否决时，副核（第二核验模型）升顶级复核档再核一次，仍不一致转人工。
- 降档须用户放行：只有用户明确说「再省一点」时，才允许把部分岗位切到免费备选档，且切后退回率明显上升即切回默认档位。

选型方法上有两条纪律。其一，团队不凭印象排除任何模型：每次制定或修订分派表，必须对平台当前提供的全部模型逐个给出纳入或排除的理由并留痕（例如某模型专长前端页面审美、与本团队任务特性不符，某模型为旧版本、被同家族新版取代，均记录在案）。其二，免费与限免标签时效性强，倍率与标签以修订当日的客户端清单为准，并在规范中注明快照日期；来自单一评测来源的能力结论只作为待验证假设使用，须为相应岗位配置替补链（按序接替的备选模型），实测退回率上升即切换替补。

成本统计：每次任务收口时，团长运行专用脚本从会话转录中读取积分记录，按模型归集团员消耗——平台对团员请求逐笔记账，顺序运行的成员可精确归属到模型，并行运行无法唯一归属的部分如实记为未归属；团长自身请求平台不逐笔记入转录，以账单为准。最终交付时输出各模型积分表，供成本复盘与模型分派调整。

# 协作流程

每个任务按五个阶段推进，阶段之间以标准化交接物传递上下文；开工之前必须完成需求确认，未确认不得开工；每份回传按四个维度验收，不达标退回，同一成员最多两轮。

## 五阶段流水线

五个阶段的进入条件、主要工作与收口判据如下表。收口判据全部为可数条件，不写应当注意式的要求。

**五阶段流水线**

| 阶段 | 主要工作 | 收口判据 |
| --- | --- | --- |
| 输入消化 | 解析多格式材料，按维度抽取并逐条标注来源 | 输入消化清单全部通过 |
| 调研分析 | 行业、政策、客户三方向并行研判 | 三类结论齐备且标注不确定性 |
| 方案组装 | 产品、架构、案例、数据组装分层方案 | 每条结论登记落地载体 |
| 叙事成稿 | 按受众组织叙事与表达 | 跨源一致性通过且内容冻结 |
| 核验出件 | 独立核验后渲染正式文档 | 文档自检全部通过且完成对账 |

## 开工前需求确认

在任何阶段开始之前，总编排必须亲自向任务发起人逐项确认交付方向，未确认禁止建立团队、禁止开始写作。这一步针对返工失控的根源：方向偏差一分，后续全流程的劳动都建立在错误前提上。

确认采用逐支深度追问的方式执行。总编排先亮出本次需要确认的三至六个决策分支——交付物形态、受众用途、范围重点、素材口径、约束边界、验收标准，让任务发起人看到问题全貌；然后从最基础的分支问起（通常是交付物形态或受众用途，其他分支的问法取决于它们的答案）；一次只问一个问题，问题附三件内容：答案会影响哪部分交付、两至四个选项、推荐项及各自后果。任务发起人用短语即可作答。

追问有防疲劳设计：单次会话不超过八个问题；任务发起人任一时刻可以说按推荐执行，追问立即结束，剩余分支按推荐值处理并标注可随时以一句话更改；也可以说一次列全，改为批量作答。确认完成后，全部决策固化为需求简报，作为全流程的第一份常驻依据，后续阶段的每次任务派发都携带该简报。

## 阶段间交接

阶段之间以标准化交接物传递上下文，这是防止口径漂移的核心设计。交接物的必含字段包括：任务三要素（谁写什么文件、发给谁看、要达到什么目的）、本阶段任务指令、上游已确认结论及其来源标签、待澄清项与假设、约束与红线、验收清单。下游成员只消费交接物，不向前序成员索取信息。

交接物按最小必要原则下发：只装入下游完成本阶段所必需的内容，其余已确认结论保留在总编排侧的可追溯链中，下游需要时按引用标签调取。这样做的依据是，无关内容占据上下文会降低判断质量，与信息缺失同样有害。

成员回传统一采用四段式：结论、依据、待确认、状态。总长不超过八百字，结论不超过五条。回传不写过程叙述、不作自我评价、不自行增立规则，超过篇幅即退回重写而非压缩——篇幅超标通常说明主次未分清，压缩只会把未想清的部分隐藏起来。

## 验收与退回

总编排对每份回传按四个维度验收：完整性（是否覆盖任务指令全部子项）、可追溯性（每条结论是否有来源）、假设标注（未确认前提是否标明置信度）、上游一致性（是否与已确认结论矛盾）。判定结论只写通过、修订后通过、不通过三种，不写基本可以、整体尚可。

不达标的回传附具体缺口退回修订，同一成员最多两轮；退回时须附结构化失败归因，指明第一个出错的步骤与根因类别，供核验岗复核。超限仍不能达标的结论不掩盖、不代写，标注待确认并列入交付时的待澄清清单，必要时交任务发起人裁决。

# 质量保障机制

质量由三层防线分担——开工前把方向问清、过程中每条结论带来源、外发前独立核验加对账；协作纪律全部写成可数指标，任何一层拦截失败，下一层仍然有效。

## 三层防线

- 第一层，开工前需求确认：逐支深度追问，交付方向经任务发起人确认后才开工（见第三章）。
- 第二层，过程来源强制：每条结论标注来源，阶段验收按可数判据执行（见本章后文）。
- 第三层，外发前独立核验与交付对账：核验岗独立判定，出件自检全部通过才允许交付（见本章后文）。

## 结论可追溯

团队规定无来源结论数为零：每条关键结论必须标注出处，出处可以是事实来源、政策编号或上游结论的引用标签。成员引用其他成员的结论时使用统一格式的引用标签，标签可回溯到具体成员与具体结论条目，形成覆盖全流程的可追溯链。

调研类任务另须执行来源分级：一手来源、二手来源、低质来源分列登记，事实与推断分开标注，证据不足的结论标注待确认。团队的原则是：不确定的结论宁可标注待确认，不写成确定结论。

## 量化纪律指标

协作纪律全部写成可数判据，不依赖自觉遵守。核心指标如下表，取值均来自团队现行规范文件。

**协作纪律量化指标**

| 指标 | 取值 | 作用 |
| --- | --- | --- |
| 无来源结论数 | 0 | 无出处结论不采信 |
| 未标置信度的假设数 | 0 | 假设必须显式标注 |
| 同一结论翻转次数 | 最多一次，第二次须附新证据 | 防止反复改口 |
| 同一议题往返轮次 | 不超过两轮 | 防止无限往返 |
| 对同一成员的单阶段消息数 | 不超过三条 | 倒逼任务边界划清 |
| 同阶段并行成员数 | 不超过三人 | 防止验收瓶颈与信息干扰 |
| 单次追问问题数 | 不超过八个 | 防止问询疲劳 |
| 同一成员修订轮次 | 最多两轮 | 超限转待确认处理 |

## 外发前核验与交付对账

成稿后由核验岗独立核验。核验岗只消费上游结论、只做核验不补写，逐项核对事实来源、表述合规与数字一致性，给出三级判定：可进入使用、修订后复核、禁止外发。越界表述（例如把仅在特定场景验证过的能力表述为已部署）一律判禁止外发。

文档渲染完成后先运行脚本自检，覆盖章节数量、标题编号、表格完整、字体字号、红线保真、关键内容等十六项，其中样式生效类判据四项：套用表格样式的段落中直接字体字号数为零、含图片对象的段落未套图片样式数为零、表题与图题角标的直接字体字号数均为零；同时表题数须与多列表格数严格相等，多套或漏套都判不合格。全部通过才允许交付。样式合规从"套了就算"升级为"读回证明生效"，仅做居中对齐或套了样式但字号被直接格式覆盖，都不算通过。涉及改页的任务另须执行对账：把每个改动关键词定位到文档实际位置，与改动清单逐项比对，超出清单范围的命中立即回问。判定的最终依据是磁盘上的实际文件，不是口头汇报——成员汇报已完成不等于产物存在，以打开实际文件核对的结果为准。

# 变更与风险控制

成稿后先冻结基线，任何修改先算影响面再动手；平台故障、任务中断、汇报与实物不符三类异常有预置处置规则；沟通回传有长度与内容硬约束，过程性内容一律不进交付链。

## 内容冻结与变更管理

叙事成稿后先打内容冻结基线：源文件、结论与载体的映射表、版本号一并存档。此后任何修改一律对基线做差异比对，不在最新版本上零散修改，保证每次变更的影响范围可查、可回退。

变更本身执行固定流程：第一步先填写三列——影响哪些载体、影响哪些结论、需要重做哪些段落；填写不出说明变更范围尚未理解，先补齐理解再动手。内容修改与文档渲染分为两段：修改阶段只改源文件，不重新渲染；确认后再统一渲染一次，防止改一句、渲一遍的成本失控。

## 异常处置

对三类典型异常，团队有预置处置规则。

- 多个成员同一时间报告同一错误：按平台故障处理，停止派发、不再重试，已落盘产物以最后一份完整文件采信，版本号冻结。
- 单个长任务被中断：先检查产物完整性，完整则采信并注明可能缺少最后一步；不完整则重派一次，仍失败由总编排接手并记录。
- 成员汇报已完成但给不出文件路径：一律按未交付处理，要求提供磁盘路径，以实际文件为准。

## 沟通降噪

成员回传执行长度与内容双重硬约束：四段式结构、总长八百字以内、结论五条以内；过程叙述、自我检讨、自行增立规则、含糊自评四类内容出现即收束，固定只保留更正后的结论。过程性内容写入项目工作笔记留档，不进入交付链——对下游有用的只有结论本身。

# 持续改进

每次交付中暴露的问题固化为编号经验并写入规范或脚本，累计三十八条；规范文件的修改走提案与独立审核流程，锁版本、留痕、可回滚。改进不依赖记忆，依赖检索与脚本拦截。

## 经验索引

团队把真实交付中暴露的每个问题固化为一条编号经验，目前累计三十八条。每条经验包含四项信息：发生场景、教训、修复方式、固化位置——即该问题已写进哪份规范或哪个脚本。执行任务前先查经验索引，同一类问题不重复发生。

经验来源全部是实际事件，例如：表格列宽按列数均分导致长表头文字竖排，修复方式下沉到渲染脚本，任何调用路径都正确；页码统计的接口调用顺序错误导致连接中断，修复方式固化为专用导出脚本；改动清单与实际文档不一致，靠逐页对账脚本拦截。修复的共同取向是把人要记得的规则，变成脚本会拦的约束。

## 知识更新治理

协作规范文件是全队唯一依据，对其任何修改执行提案流程：提出最小改动并附证据引用，经独立审核通过后合入，锁定版本、留痕、可回滚，不允许在任务执行中随手修改。规范与配套校验脚本同步维护，修改校验脚本须先通过其内置自检，防止用失效的尺子量产出。

# 开源复用指引

文件包按角色定义、协作规范、出件脚本、样式模板四类组织；复用的建议路径是保留调度与纪律骨架、替换角色与知识库、沿用或替换渲染脚本；诚实红线不建议裁剪。

## 文件包结构与重建

团队文件包的核心目录包括四类：角色定义，每名成员一份角色文件，写明职责、工作规范与产出结构；协作规范，二十余份中央规范文件，覆盖沟通协议、验收标准、文档格式、证据规则、知识治理等各方面；出件脚本，文档渲染与自检脚本，把版式要求与协作纪律固化为可执行代码；样式模板，正式文档的标准模板，含标题自动编号、封面、目录与题注样式。

重建一套面向自己领域的团队，路径分三步：保留总编排角色文件与协作规范作为调度与纪律骨架；把成员清单替换为本领域的角色（角色数量与命名均可调整）；把知识库替换为本领域的来源与索引。渲染脚本与样式模板可以整套沿用，也可以替换为目标平台的等价实现。

## 可裁剪与可改造点

- 角色可增删：精简编队规则允许按任务裁剪成员，启用判据（该角色缺席时结论是否改变）与领域无关。
- 纪律可沿用：量化指标、四段式回传、验收四维度与具体业务无关，可整体沿用。
- 脚本可替换：出件与自检脚本可换成目标平台等价物，但建议保留自检门槛，防止只渲染不核对。
- 诚实红线建议保留：诚实边界是交付可信的前提，裁剪其他内容不应裁掉红线。

首次复用建议先执行一个中等复杂度的任务，对照第四章的量化指标核对执行情况，再决定裁剪幅度。指标中往返轮次、修订轮次与自检通过项三项最能反映纪律是否仍然有效。

## 适用与不适用场景

适用的任务形态：调研报告、客户技术方案、申报材料、投标论证等长材料生产；多来源材料需要统一口径与来源核验的场景；需要过程可追溯、多轮修订且要求每次改动影响可控的场景。

不适用的任务形态：需要实时响应的交互式任务；没有任何可核验素材、要求直接给出确定结论的任务——团队的设计会如实返回待确认与假设，而不是给出编造的确定结论；单页短文档等轻量写作，完整流程的开销不经济，此类需求可裁剪为单角色执行。

## 获取与版本

完整文件包随本项目发布渠道提供，获取地址与最新版本以项目主页公告为准。本文档描述的机制对应团队版本 1.5.0，为当前标准状态；后续机制调整直接修订本文档正文，逐次变更的流水见变更记录与发布公告。

## 附录：诚实红线

- 未在特定行业或客户验证的能力，不得表述为已在某行业使用或已部署；已验证能力向新场景迁移，建议通过轻量验证确认。
- 引用第三方科研或测试报告时，报告结论与其适用边界须同源同文出现，不得单独引用结论。
- 降本、增效等数字均为示意测算，须标注假设与置信度，实际以落地验证为准。
- 材料、部件的标称值仅作参考，须以来样实测值为准，差异点显式说明。
- 精度指标仅在标定适用范围内表述，超出适用范围（如极端工况）须标注假设，不在边界外推。
- 新行业或新场景的适配为假设，建议通过小规模验证确认，不得写成已确认能力。
