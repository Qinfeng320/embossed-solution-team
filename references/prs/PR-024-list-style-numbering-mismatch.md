# PR-024：修复 List Bullet 注入样式的编号错位（列表与标题共享计数器）

- 日期：2026-11-17
- 类型：缺陷修复（脚本，`scripts/build_docx.py`）
- 状态：已合入

## 现象

用 `assets/样式模板.dotx` 渲染含 `bullet` 块的文档树时，正式件出现编号错乱：

- 列表条目显示"二·/三·/…/二十五·"这类全局递增中文序号，而非项目符号；
- 章号被推高（第二章"团队构成"显示为"八"）；
- 小节标题显示"12.1·三层防线""18.2·""21.2·"等异常编号。

用户在《售前专家团运作机制详解》正式件中报告（6 处页面截图），首次交付的渲染抽检未覆盖列表页，漏检。

## 根因

`_ensure_list_styles()` 在模板缺 `List Bullet` / `List Number` 样式时，从 python-docx 默认模板注入样式定义，但**只拷贝样式元素、未拷贝其引用的编号定义**。注入样式的 `numPr` 引用 `numId=1`，而本包模板 `numbering.xml` 中 `numId=1` 是 heading 1-6 的中文多级编号（chineseCounting）。结果：所有 `List Bullet` 段落在 `ilvl=0` 上与全部一级标题共享同一计数器，编号全局连续递增。

属"编号 id 跨模板错位"类缺陷：样式引用的 numId 只有在源模板的编号表里才有意义，换模板后指向完全不同的定义。

## 修复（`scripts/build_docx.py`，最小 diff）

1. `_ensure_list_styles()`：注入样式后剥离其自带 `numPr`，切断对目标模板编号表的任何引用；
2. 新增 `_disable_numbering()` / `_render_list_item()`：列表条目渲染为 `List Bullet` 样式 + 段落级直接格式 `numId=0`（双保险禁用继承编号）+ 确定性前缀（bullet 用"· "，numbered 用"1. "）；
3. `_render_block()` 的 bullet/numbered 分支与红线附录 sources 渲染点改走 `_render_list_item()`。

列表符号/编号权由脚本确定性生成，不再依赖模板 numbering；悬挂缩进仍由 `make_docx.fix_lists()` 统一设置。与"渲染下沉脚本、确定性出件"的机制一致。

## 验证

- 重渲染《售前专家团运作机制详解》：20 个列表段落全部 `numId=0` + "· "前缀；章号恢复"一/二/…/七"，小节标题恢复"4.1/7.2"格式；
- 全部出件闸门复跑通过（自检 12 项 / 文风终扫 0 命中 / 文本规范化 / 元数据清洁 / 渲染成图抽检含列表页）。

## 防复发提示

- 渲染成图抽检必须**覆盖含列表块的页面**，不能只抽封面与表格页（本次漏检原因）；
- `check_style_words.py --paths <目录>` 扫描目录时会把渲染 PNG 二进制误读为文本命中，应显式指定文本源文件。
