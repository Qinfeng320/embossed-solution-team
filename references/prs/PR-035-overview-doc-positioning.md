# PR-035 自述文档定位澄清：标准说明而非更新日志（2026-11-19）

## 问题
自 1.5.0 发版起，`references/team-overview.md` 内含「发布记录」表，逐次登记版本号、发布日期与变更要点；本轮文档同步又追加一行。用户指出：这份文档的定位是维护一份**标准的文字说明**（描述团队当前的标准机制与现状），应与**传统的更新记录**区别清楚，不应把逐次变更流水写进来。

## 根因
把"文档同步纪律"（变更合入后要更新文档）误解为"把变更本身记进文档"。该纪律的本意是让文档反映**最新标准状态**，而非在文档中累积一条变更时间线。变更流水已有专门载体——变更记录（PR）与发布公告，两者职责未分清。

## 修复
- `references/team-overview.md`：删除「发布记录」整节；头部新增「文档性质」声明——本文件是标准说明，随机制调整直接修订正文使标准为现行；逐次变更流水由变更记录与发布公告承载，不在本文件累积。"获取与版本"节改为当前标准状态口吻。
- Word 文档树 `embossed_projects/team-doc-20261117/tree.json`：同步删除「发布记录」节、项目定位节补同样的文档性质声明、获取与版本节改为标准状态口吻；重渲 `售前专家团_运作机制详解_20261119.docx`，十四项自检通过。
- `references/prs/PR-034-docx-style-effective-gate.md`：更正"新增发布记录节"的记录，并标注由本 PR 更正。
- `references/governance.md` §二'：补一条载体分工，明确标准说明与更新记录的边界。

## 载体分工（本次确立）
| 载体 | 记什么 | 不记什么 |
| --- | --- | --- |
| team-overview.md（标准说明） | 团队当前的标准机制与现状，随调整直接修订正文 | 逐次变更流水、版本号演进时间线 |
| 变更记录（PR）/ 发布公告 | 每次变更的问题、根因、改法、验证与日期 | 长期有效的机制全貌 |
| Word 正式件 | 任一时刻标准说明的导出快照 | 不回写维护版，不入专家包 |

## 验证
- Markdown 与 Word 均无「发布记录」节，无变更要点表残留。
- 两份均含文档性质声明与"当前标准状态"口吻。
- 本轮机制改动（样式生效规则、十四项判据、三十七条经验）仍在正文，未因删除发布记录而丢失。
