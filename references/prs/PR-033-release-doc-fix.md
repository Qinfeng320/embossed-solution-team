# PR-033：修正发版说明失真（一键脚本失联）

- **日期**：2026-11-17
- **版本**：1.5.0 → 1.5.0（文档修正，不升版）
- **性质**：文档维护（消除文档与实物不符）
- **触发**：1.5.0 发版后用户追问"一键构建脚本是什么东西"，查证发现README 与经验索引长期引用一个已不存在、源码无留存的脚本。

## 问题事实

1. `_backups/package_release.py`（PR-015 建立的一键发布脚本）在 2026-10-29 的生效核查中已记录"连同整个 `_backups/` 目录缺失"，本次全盘搜索确认仍不存在，历史版本记录中亦无源码留存。
2. 包内 README「打包分享」段仍写"一键出发布包"并给出该脚本的调用命令；经验索引 L-10 标"已固化"并指向该脚本——构成文档描述不存在工具的失真。
3. 根因：该脚本位于专家市场维护区（包外），不在 `verify_package_coherence.py` 的包一致性校验范围内，失联后无机器闸拦截，仅靠 10-29 一次性核查留痕，后续未回改文档。
4. 脚本的存在前提也已消失：其核心价值是移出 hooks 禁项，而 hooks 已于 2026-11-16 彻底移除（PR-019/L-28）。

## 改动内容

1. `README.md`「打包分享」：删除一键脚本引用，改为官方工具三步流程（校验 → 注册 → 打包）+ 打包后手工重命名与构建说明，并说明旧脚本为何不再适用。
2. `references/lesson-index.md` L-10：改写教训——从"用一键脚本构建"升级为"固化脚本须与文档同步存续，包外产物不在一致性校验范围内、失联后须回改文档"；固化位置改指 README 与 PR-015/PR-033；状态由"已固化"改"已修订"。

## 验收

- 全包 grep `package_release.py`：仅 PR-015（历史记录，不改）、L-10（已标注失效）、README（已说明失效）三处提及，均为"说明其失效"语境，无"仍在使用"的引用。
- 本次为文档修正，不改变团队机制、角色、模型分派、流程闸门与量化指标。
