# PR-026：模型分派规范（按岗位特性分级派模型）

- **日期**：2026-11-17
- **版本**：1.3.0 → 1.4.0
- **性质**：能力新增（成本优化）
- **触发**：用户反馈"专家团写一个文档模型消耗太大"，要求按各团员工作特性分派最合适的模型以节省积分，模型全部限定 WorkBuddy 平台提供的四种（GLM 5.3 / MiniMax M3 / DeepSeek V4-Pro / DeepSeek V4-Flash）。用户拍板：改包固化＋质量优先档。

## 改动内容

1. **新增中央真相源** `references/model-dispatch.md`：模型分派表（旗舰档 GLM 5.3＝团长/mat/ver；强推理档 DeepSeek V4-Pro＝ind/pol/cus/pro/arc/cas/dat；快省档 DeepSeek V4-Flash＝doc-in/docx；均衡备选档 MiniMax M3 备用）、升降档规则、兜底映射、成本口径（如实标注不掌握单价）、派活自检清单。
2. **团长文件两处**：§2.3 真相源清单登记 model-dispatch.md；任务分配总纲新增「模型分派表」小节＋派活三条硬规则（两轮退回自动升档 / 四岗永不降档 / 双核验用两个模型家族）。
3. **plugin.json**：版本 1.3.0 → 1.4.0，中英文描述补模型分派能力。

## 设计决策（备查）

- **质量优先档**：只把确定性高、无判断风险的岗位（doc-in 结构化抽取、docx 脚本渲染辅助）降到快省档；判断密集的调研/方案七岗用强推理档；成稿（mat）与外发闸门（ver）两道质量关口加团长保持旗舰档。
- **落点选择**：角色定义文件的头部字段不支持声明模型（平台机制：模型在派活工具参数与开会话选择两处），故分派规则写进团长派活总纲＋中央真相源，成员文件不动。
- **安全阀**：两轮退回自动升一档；降档须用户显式说"再省一点"且仅限 cus/cas/pro；团长/ver/dat/mat 永不降档；关键件双核验按既有规则跨模型家族执行。
- **兜底映射**：派活接口不接受具体模型名时按档位路由（旗舰=默认 / 强推理=推理路由 / 快省=轻量路由），宁升不降。

## 影响面

- 团长派活行为变化：每次派活须指定模型档位并写进任务卡留痕。
- 成员行为无变化（成员不自知模型档位，规则在团长侧）。
- 对既有 PR 无冲突；grill 协议（PR-023）与本 PR 均新增于团长文件，互不重叠。

## 验收

- `verify_package_coherence.py` 全绿；`validate_expert.py` 通过；`register_expert.py` 重新注册完成。
- 分派表覆盖全部 12 个角色，无遗漏；永不降档岗（团长/ver/dat/mat）与降档白名单（cus/cas/pro）无交集。
