# PR-021 · 任务三要素规范（全团任务定义骨架）

> 版本元数据：`PR: 021` ｜ 提出 2026-11-16 ｜ 状态：已合入 ｜ 关联经验：L-30

## 一、起因与目标

用户框架原文要点：**"拿需求、写作之前要确认好——谁要写什么文件、发给谁看、要达到什么目的；这也是整个专家团在运作时要明确的内容。"**

现状缺口：三要素此前未被显式定义为贯穿全团的骨架，只零散体现在 G-1 六要素与各章。目标：立中央真相源，把三要素固化为**全团任何任务开工前的定义标准**，并贯穿需求确认、任务派发、产出验收三层。

## 二、三要素定义（缺一不可）

| # | 要素 | 必含子项 |
|---|---|---|
| ① | **谁写什么文件** | 执行主体 + 交付物名称 + 形态 + 落盘路径/篇幅 |
| ② | **发给谁看** | 受众画像 + 内部/外发 + 使用场合 |
| ③ | **要达到什么目的** | 核心目标 + 可数成功判据 + 业务关联 |

判据：把三要素交给任一成员，他不追问即可开干 → 定义合格。
