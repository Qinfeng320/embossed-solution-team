# 文风与文档卫生规范（Style Guide）

> **版本元数据**：`version: v1.3` ｜ 生效 2026-10-14 ｜ 状态：现行有效 ｜ 合入 PR：`references/prs/PR-008-claim-evidence-and-proposal-structure.md`（v1.1 系 PR-006 修订内容、v1.2 系 PR-007，原头部未同步部分已补正）
> **中央真相源之一**。本文件定义专家团**对外/正式交付文档**的行文红线、工作痕迹清除、文体规范、受众适配、正式件与准备件分离、文本规范。与 `redlines.md`（诚实边界）、`document-format-standards.md`（格式标准）并列，构成输出侧规范体系；全团引用，不得各写各的。

## 一、行文红线（词汇层面）

### 1.1 三类禁用词

正式交付文档中**不得出现**以下三类词汇（用户历次明确要求，2026-10-12 两次强调）：

| 类别 | 禁用词（核心表） | 说明 |
|------|------------------|------|
| **A 军事化/狼性类** | 作战、作战地图、打法、主战场、卡位、硬仗、铁军、狼性 | 军事化修辞与狼性话术，正式商务文件中一律不用 |
| **B 互联网黑话类** | 抓手、钩子、赋能、对齐、拉通、颗粒度、复盘、沙盘、压舱石、翻车、闭环 | 互联网行业黑话与隐喻；"对齐/闭环"按 §1.2 例外判读 |
| **C 市侩/江湖气类** | 通吃、搞定、拿下、卖点、爆款、抢窗口、占位、抢占 | 市侩腔、进取腔、江湖气说法 |

**单字类提示**（不自动匹配，人工判读时留意）："抢"（抢窗口/抢时机/哄抢式表述）、"攻"（注意与"攻关"的区别）等单字进取腔，如构成上述语义即改写。

**改写方向**（示例）：
- "主战场" → "规模场景" / "主要应用场景"；
- "抓手" → "手段" / "措施"；
- "占位" → "占据"（或按语境改写）；"抢窗口" → "把握窗口"；
- "对齐"（黑话语义，如"方法论对齐"）→ "参照" / "保持一致"；
- "翻车" → "公开演示失败"（客观陈述）；
- "复盘" → "回顾" / "总结"（对外文档）。

### 1.2 行业术语例外（不判违规，须记录依据）

以下语境中的命中项**不判违规**，但 ver 核验时须标注依据：

1. **排版/设计术语**："对齐"与方位词连用——左对齐、右对齐、居中对齐、两端对齐、垂直对齐、水平对齐等（格式描述必备词）；
2. **质量/工程管理固定搭配**："闭环"用于专业表述——整改闭环、闭环管理、验收闭环、闭环控制（质量管理、控制论等有行业文献依据的用法）；
3. **科技语境**："攻关"（技术攻关、科技攻关，为科技工作标准用语；注意"攻坚"类军事化近似词应按语境审慎使用）；
4. **其他**：确属真实行业固定用法（有行业文献/标准依据）的，可保留，由 ver 核验时记录依据，不得以"行业术语"名义规避整改。

### 1.3 判定与执行

1. 交付前须执行**终扫**：`python scripts/check_style_words.py --paths <交付件目录>`；
2. **脚本是筛子不是法官**：命中项须由 ver 逐条按上下文判读——确属违规的改写；属例外的记录依据；判读结论进核验输出；
3. **目标**：对外交付件三类禁用词命中 = 0（已记录依据的例外项除外）；
4. 扫描须覆盖全文（含表格单元格、页眉页脚——`check_style_words.py` 已按"全 XML 去标签"口径实现，不遗漏）。

### 1.4 书面语标准（正式件行文 · PR-007 新增）

正式交付材料（提交领导/客户、投屏展示、学习与汇报材料）的行文须**正式、严谨、书面**；以下口语化、俚俗化与教学腔表述不得进入正文（保持信息不变，以平实书面语改写）：

| 类型 | 典型表述（禁用） | 改写方向（示例） |
|------|------------------|------------------|
| 口语动词/短语 | 吃透、钉牢、铺开、上手、过一遍、补课、看全貌、说清、搬用 | 系统梳理、明确、解析、先行阅读、逐条详述、厘清 |
| 俗语化标签 | 对号入座、收尾 | 规范身份、小结 / 整体框架 |
| 比喻/意象 | 三个抽屉、另一种切法、弹药库、护栏、物理支点 | 直接陈述（如"可用于技术选型说明""关键论据""物理基础"） |
| 教学腔 | 记住这条链、记成、不必背数字 | 可说明……、核心可概括为……、掌握方向性判断即可 |
| 反问/设问式 | 客户问"……"，答案就在…… | 可回应……类提问（依据……栏） |
| 自夸/程度词 | 最有说服力、最不容易被挑错、最有力 | 较具说服力、关键论据（并保留可核验依据） |

- **人称与指代**：不用"自家/咱们"等口语指代（改"公司 / 本路线 / 该技术路线"；自我指称规范另见 §4.2）；面向外部受众的材料避免未定义的第三人称指代（如"用户"）；
- **判定**：本节清单由 ver 按上下文逐条判读；命中即改写；确属引文（原文照录）的予以保留并记录依据。

### 1.5 AI 生成腔弱化清单（PR-008 新增 · 提示级，与 §1.1 分表判读）

**定位**：§1.1 三类禁用词是**硬红线**（对外交付件命中 = 0），判"公司口径违和"；本清单是**质量提示**（不清零），判"AI 生成腔"——两类**分表、分口径判读**，不得合并统计。词表来源：外部 Skill `academic-humanizer` 通用 AI-tell 目录的汉化改造（剔除学术专属与英文字面条款），部分与 `claim-evidence-discipline.md` §四配套。

| 组 | 类型 | 典型表述（提示候选，非绝对禁用） | 判读与改写方向 |
|----|------|--------------------------------|----------------|
| **E1** | 意义拔高（无具体依据时） | 注入新的活力、迈上新台阶、开启新篇章、里程碑意义、填补空白、颠覆性的、革命性的 | 有具体依据的保留并记录依据；无依据的删除或改为具体判断 |
| **E2** | 空泛程度宣称（无支撑时） | 极大地、全方位地、多维度地、深层次地、助力（作空泛动词时） | 绑定具体数量/范围，或改为定性陈述（配套 `claim-evidence-discipline.md` §四） |
| **E3** | 回避系动词 | 起到了……作用、扮演着……角色、发挥着……作用（可直接写"是/承担/负责"时） | 改为直接表达；确需强调职能的按语境保留 |
| **E4** | 空洞收尾 | 具有广阔的应用前景、未来发展可期、必将大有可为（无后续具体内容时） | 改为具体判断或计划；有实指内容的保留 |
| **E5** | 升华式成对结构 | "不仅是……更是……"（同篇多次出现时） | 保留一处，其余改直述 |
| **E6** | 三段式填充 | 为凑成三项而并列的排比（实际只有两项或数量不定时） | 按实际数量排列，不硬凑三 |

**密度控制项（不判违规，超密度须改进）**：

| # | 项 | 密度上限（参考） |
|---|----|------------------|
| 1 | 模板化强调（值得注意的是 / 需要指出的是 / 应当强调的是） | 合计每千字 ≤ 2 次（§3.1 允许"值得注意的是"作论断句起头，此处只控密度） |
| 2 | 连接词连续开头（此外 / 同时 / 并且） | 连续不超过 2 句 |
| 3 | 同一指代对象的称谓轮换（该方案 / 此方案 / 本方案） | 同一段落内不超过 2 种 |

**判定纪律**：E1–E6 命中由 ver 逐条判读——属 §1.2 例外、引文原文、固定表述（`claim-evidence-discipline.md` §1.2）的记录依据后放行；违规项按该文件 §四处理。**本清单不进入 §1.1 清零口径**；脚本以第二档（`--weak`）提示级输出。

## 二、工作痕迹（8 类禁入正文）

正式汇报/交付正文中**禁止出现**以下 8 类工作痕迹（源自真实交付的逐轮清理结论）：

| # | 类型 | 错误写法（示例） | 正确处理 |
|---|------|------------------|----------|
| 1 | 勘误/纠错过程叙述 | "经核查，GB 28010 不存在，正确编号为……" | 只写结论与依据；必要的纠错以"须注意……"客观陈述 |
| 2 | 前期材料引用错误说明 | "立项材料中曾引用……" | 删除（旧材料勘误属内部质量管控，不入正文） |
| 3 | 取证过程叙述 | "法规正文未取得""通过某平台检索""扫描件核验" | 改写为客观来源陈述，或删去过程 |
| 4 | 调研动作叙述 | "本次调研""梳理过程中""需说明的是" | 删除，直接进入内容 |
| 5 | 待补事项标注 | "待补""暂未获取""需客户端输入" | 内部清单留存；正文改写为条目本身的事实描述 |
| 6 | 信源可信度自评 | "该数据来源有限""可信度中等" | 删除；来源限定按 `redlines.md` 的 caveat 规则自然陈述 |
| 7 | 内部代号/阶段标记 | "v3""初稿""修订版"等版本过程标记 | 删除；版本信息只保留在规范的版本字段 |
| 8 | 引导式元话语与自述式元描述 | "本章将……""下面我们来看"；**自述式元描述**："（一句话讲透）""（本页核心交付）""（重点展开）""（浓缩索引）"；**内部编辑指示**："应当保留，不要删" | 删掉引导句与元描述，直接写内容；编辑指示属工作底稿信息，不入正文 |

**原则**：**只写结论，不写得出该结论的过程。**

**与 `redlines.md` 的边界**（勿混淆）：
- **诚实边界必须保留**——第三方报告 caveat、假设标注、"该数值为内部测试数据"性质标注等，属"诚实披露"，**不得**当作工作痕迹删除；
- **过程叙述必须清除**——勘误过程、取证动作、调研动作等"工作过程"，不得混入正式正文。
- 判定口诀：**保留诚实、清除过程**。

## 三、文体规范（按交付类型）

### 3.1 研究报告体裁（调研/研究报告类交付）

- **开篇**：摘要式导语（点明目的与梳理范围，不写"本文档分为X部分"式元话语）；
- **标题命名**：小节标题本身即论断（如"从量化门槛到规范空白"），不堆叠"分析/概述/简介"式空词；
- **段落结构**：以论断句起头（"值得注意的是……""就覆盖范围而言……"），后接论据与数据支撑；小节末尾给结论性判断或工程含义，不停留于事实罗列；
- **术语**：中英并置（首次出现），如"防夹系统（Anti-Pinch System）"；
- **句式**：长句为主，逻辑连接词丰富（值得注意的是 / 然而 / 此外 / 就……而言），破折号引出解释。

**结构模块（按需组合）**：执行摘要 → 背景 → 正文分节 → 综合分析 → 结论 → **局限** → 参考资料（链接完整、可点击）。"局限"一节如实列出：方法边界、数据缺口、未能访问/未能核实的部分、未开展的验证。

**篇幅分档（按复杂度定，宁精不冗）**：直答型 500–1000 字；专题分析 1500–3000 字；综合研究 2000–4000 字。

**文体与排印**：以自然段为主（prose）；列表仅用于并列项与数据呈现；不使用表情符。

### 3.2 商务方案体裁（客户版方案类交付）

按 `mat-agent.md`「正式客户版口吻规范」执行（以客户为中心、价值主线、诚实边界内化、去防御措辞）。本文件其余条款（禁用词、工作痕迹、受众适配、文本规范）两套文体共同适用。

### 3.3 操作/搭建手册体裁（执行说明类交付）

- 面向"照做的人"：不写设计论证与背景铺陈，直接给参数与步骤；步骤用 ①②③ 悬挂缩进编号；
- 结构模块（按需组合）：总览 → 清单（采购/材料/工具）→ 分步制作装配 → 连接（电气/管路）→ 通电前检查 → 常见问题处理；
- **可执行性优先**：工程参数与尺寸进入正文（供执行方使用）；效果图仅作形态示意，并声明"非执行依据"（见 §六）。

### 3.4 汇报件结构原则（投屏/汇报类交付）

- **重点前置**：核心数据与关键内容排在前面；次要信息后置但保留，不删除；
- 叙事顺序：结论 → 依据 → 请审议事项；页面只留纯内容（见 §五）。

## 四、受众适配

### 4.1 数值颗粒度（按受众视角）

- 受众为**管理层/市场视角**的汇报材料：**技术性能参数不进入正文**，一律定性化处理——
  - "0.05MPa 量级" → "单位面积上的压强很低"；
  - "零下 30℃ 至 80℃" → "极低温至高温的宽温域"；
  - "毛利削薄 12%" → "对利润形成明显放大效应"。
- 技术数值保留在**内部技术文件**；受众为技术评估方（技术评审材料）时按需保留并标注口径；
- 判定归属：由团长在交接物声明受众类型（管理层/市场向 vs 技术评审向），mat 按此执行、ver 按此核验。

### 4.2 自我指称

正式对外材料避免高频"我司/我方"自称（尤其管理层材料），改客观陈述或按主体改写（"供应商/公司/本项目/自行"）；确需主体归属时用中性表述。目标：全文自称词计数按交付件口径收敛为零或最小集。

### 4.3 语气

- **降调**：强指令词（必须/务必/严格/立即/抓紧）按语境降调为平实表述（需/需要/应当/按……执行）；典型对照："必须进入"→"需进入"、"顺序是硬性的"→"顺序无法颠倒"、"不显著增成本"保持客观；
- **保留法规性术语**："强制"（强制性标准、强制效力）等法规用语按原义保留；
- **就事论事**：避免煽动性修辞、进取腔、夸张断言；专业、严谨、可核验。

### 4.4 正式件书面语与内部信息中性化（PR-007 新增）

材料面向**领导 / 客户 / 投屏展示**场景时，除 §1.4 书面语标准外，须执行内部信息中性化：

1. **内部档案代号**：`doc-in` / `ind` 等成员代号不得出现在正式件——来源标注改写为中性档案名（如 `【依据 材料解析:知识点#1】` / `【依据 行业研究:3.1 节】`）；
2. **内部角色词**：团队负责人 / ver / mat 等角色称谓不得出现——按场景改写（如"建议由公司核定""请公司确认口径"）；
3. **制作自查块**：面向制作者的自查清单、内部纪律段落不随正式件交付；
4. **敏感标识**：材料按"内部资料"保护时保留"请勿外发"类提示；确需对客户分发时单独出客户版（去内部标识并复核披露边界）。

## 五、正式件与准备件分离（投屏件纪律）

**正式投屏件**（给管理层/评审直接观看的页面、上会材料、演示页面）中**不得包含**以下准备性/元层面内容：

1. 材料分工、汇报时长、汇报目标；
2. 口播话术、讲法/节奏建议、Q&A 预判（问答准备）；
3. 现场提示、手卡、备注类内容；
4. 版本号、证据来源数量（"基于 N 处来源"）、"材料说明/数据口径备注"类汇总块——均属口述补充内容，不进入页面。

**执行要求**：
- 文件命名与页面标题**从正式角度命名**（如"上会汇报"，不用"汇报方案"；不用"面向某人的决策材料"式内部指向词）；
- 页面只留纯内容：标题、内容副题、日期、数据与来源引用；
- 准备性内容如需留存，另行制作内部文档（独立存放），不混入投屏件；
- **检查方式**：交付前扫描"分工/时长/口播/问答/预判/现场提示/节奏/材料说明/讲法"等关键词，命中即复核删除。

## 六、图示规范（PR-006 新增）

| 类型 | 用途 | 要求 |
|------|------|------|
| **效果图**（含生成式图片） | 对外展示、形态示意（决策者看） | 须声明"示意图，非执行依据" |
| **工程图**（带尺寸标注） | 执行依据（供加工/落地执行） | 与效果图配套时，以工程图为准 |
| **数据图表** | 数据呈现 | 标口径与来源；与前文数值一致 |

- **局部修改优先"图生图"**：在已认可的图上做局部改造（保留主体结构），比重新生成更稳；
- **嵌入压缩**：图片嵌入文档前按显示尺寸反推分辨率并压缩（JPEG 品质 85–90），控制文档体积；
- **多图批量生成须防重名覆盖**：并行生成后立即核对数量与顺序并重命名。

## 七、文本规范（配套 `scripts/normalize_docx_text.py`）

| # | 规范 | 说明 |
|---|------|------|
| 1 | **全角空格（U+3000）禁用** | 标题与正文的中文间隔一律用**半角空格×2**；U+3000 在部分字体（如黑体）下无字形，渲染为"方框"缺字 |
| 2 | **数字/英文紧邻空格清理** | 数字、英文与其相邻字符之间的空格全部去除（"100 N"→"100N"、"GB 11552"→"GB11552"）；纯中文之间的间隔不动 |
| 3 | **自动中西文间距关闭** | 在文档默认段属性与段落样式层面关闭自动间距（autoSpaceDE / autoSpaceDN = 0）——文本已无空格时，该渲染特性仍会造成视觉间距 |
| 4 | **学术符号禁用（PR-007 新增）** | 不用 `§`（章节符号）等学术/标准文本符号；小节引用写作"X.Y 节"（如"详见 5.2 节""（3.2 节）"）；全角竖线 `｜` 仅限引文原文与来源标题（如 PPT 原文"优选｜性价比更高"），正文分隔用"·" |

**执行纪律**：前三项由脚本一次完成（第 4 条为检查项，由 `scripts/check_style_words.py` 的"D 符号规范"组扫描）；**每次 Word/WPS 保存后须重跑**（编辑器保存可能重新引入）；脚本幂等，可安全重复运行。适用范围与 `document-format-standards.md` §九"标点与间距"配套。
